VERDICT
The G1 stop is a fair read of the reported numbers for the configuration the report represents: the reported BELOW TARGET vs R1 and NO EFFECT vs B2 trigger the plan's stop rule, and Tier B correctly does not run. But the report does not demonstrate the full preregistered protocol (results for one of six G0 checks are absent, tuning and variant reporting are absent), so this is "stop per the reported numbers", not a fully validated execution of the protocol. The report's broader conclusions (H1 refuted, topic separation strictly random, Poincare/BM25 reaffirmed) exceed the evidence and should not be treated as settled.

B. CONFIRMED - INCONSISTENCIES AND GAPS IN THE REPORT (from the artifacts alone)
B1. The report says "Gate 0 Validity Checks: 5/5 PASS" and "All preregistered integrity checks passed". The plan (Section 8) defines six checks, a-f. Results for check 8e (the controls: permute evaluation labels after frozen writes; unwritten-fact control; Tier A independent-random-association control for the true chance floor) appear nowhere in the report or JSON. So "all checks passed" is not demonstrated. Whether 8e was run is unknown - the report simply contains no 8e results. 8e is the negative control that validates the scoring harness itself.
B2. The report documents one S1 configuration (K=4, plain; 16,384 floats) and never states the beta or tau values used or whether the Section 4 grids (beta {0.1,0.3,0.5,1.0}, tau {0,1,3}) were swept or a selection was made before the test (the plan allows either, but requires it fixed and recorded). The plan's second symmetry-breaking arm (tau>0 with flat initial state, Section 6: "Both reported") is not reported. Whether other configurations (K=2, K=8, gated variants) were run is unknown - the report does not say. A run manifest or the code would settle this.
B3. Deliverable gaps vs plan Sections 7 and 12: (a) no per-seed results in the JSON, so the CIs cannot be recomputed and the per-seed distributions are invisible; (b) none of the preregistered mechanism diagnostics (effective number of experts per arm/mix, dead-expert fraction, NMI between argmax expert and true topic); (c) no recall@3, retention curve, or interference metric; (d) no total-resident footprint (state + candidate table), only state-only floats; (e) no per-write/per-query wall time or peak RAM; (f) no O1 collision count.
B4. Report Section 5.2's B4-dominance claim is selective: it quotes skewed and bursty (56.5-84.8% vs 5.8-9.8%) and omits the balanced mix, where the report's own table has S1 BEATING B4 (0.744 vs 0.541, STRONG PASS, CI [+0.174,+0.230]). The accurate summary is "B4 dominates on skewed and bursty, loses to S1 on balanced".
B5. The pilot shows a flat S1 delay curve (~0.55 at delay 10, ~0.545 at delay 1000) while B4 decays as expected (1.0 -> 0.18). Plan Section 9 says unexpected flat delay curves are reported with diagnostics. No diagnostics appear. Whether this reflects the projection/candidate bottleneck rather than memory decay is open.
B6. The report cites file:///home/akarta paths for the plan and artifacts. None of the experiment files exist in the repo at 509d70c or 531c7bb (verified by clone), so the run is not reproducible from the repo as cited. The files may be local on Nick's machine.

C. UNSUPPORTED CONCLUSIONS (claims that exceed the evidence)
C1. Section 5.1: "Preregistered Hypothesis H1 Refuted", and S1~R1 "proving that any topic separation observed is strictly attributable to random key projection partitioning".
- The confirmed numerical facts: S1-R1 aggregate equality on balanced (est -5.6e-18) and bursty (est 0.0, CI [0,0]), near-equality on skewed (0.0982 vs 0.1009). Equal aggregate means and a degenerate CI do not by themselves show the two arms' states or responsibilities were identical per write.
- Per the plan's own G4 language, these results support "no positive gain of error-driven responsibilities over random partitioning is supported" - not equivalence, and not proof of what caused the similarity.
- The cause is an open question. Hypotheses include: responsibilities stayed near-flat so S1 behaved like R1 by construction; an R1 implementation detail; or coarse discrete recall counts coinciding across seeds. The reported "effective experts = 3.98" is an aggregate usage measure; it does not by itself show per-write uniform routing or a disengaged error term. UNVERIFIED without the code and per-seed diagnostics.
- The report also omits the plan's caveat (Section 2): the recurrence is tested with fixed, untrained parameters and a negative result does not refute the paper. The trained-model question is untouched by this experiment, and the separate Sylloge/PULSAR aggregation proposal is unaffected.
C2. Section 5.3: "Reaffirmation of LTHCM & Krisis Principles - discrete chunks with explicit index structures (Poincare embeddings + BM25) vastly outperform online recurrent soft-state aggregations". No Poincare-embedding or BM25-retrieval arm exists in this experiment. The winning comparator B4 is a FIFO recency window with cosine nearest-key lookup; BM25 appears in the plan only as a Tier B stratification slice, and Tier B never ran. The tested arms say nothing about Poincare embeddings, BM25, LTHCM or Krisis. This conclusion is not supported and should be withdrawn.
C3. "No further stages (Tier B or Stage 3 GPU training) are authorized or warranted." Tier B stopping is correct per protocol. Stage 3 (learned projections on GPU) was never part of this plan; a fixed-parameter Stage 1 result does not decide it. That remains a separate decision for Nick.

D. UNVERIFIED - QUESTIONS FOR THE CODE/PER-SEED DATA (not defects)
D1. Does R1 compute its own responsibilities, and do S1's responsibilities actually differentiate per write (usage entropy and NMI per mix)? This settles C1.
D2. Report Section 2 describes check 8f as "true answer at index 0". The plan's 8f requires the answer be present exactly once; index position is not a plan requirement, and the plan's tie-break is "ties go to the lowest candidate index" (Section 6). If the implementation places the true answer at index 0, scoring ties - for example from degenerate or zero states - would resolve to the correct answer and inflate recall on those cases. This is a question, not an established defect. (O1 = 1.000 on its own is expected legitimately: the true value vector's self-cosine tops the candidate list unless collisions occur, so O1 is not evidence of tie bias.)
D3. Were the 8e controls run? If so, results should be added to the report; if not, the "all integrity checks passed" claim needs correcting.
D4. Which beta/tau/K/gated configurations were actually run, and was the pre-test selection recorded as the plan requires?

BOTTOM LINE
1. Accept the stop, conditionally on the reported numbers: per the plan's rule they halt Tier B for the represented configuration. Do not present it as a fully validated protocol execution (B1-B3 open).
2. Do not treat H1 as refuted, the "strictly random" attribution as proven, or the Poincare/BM25 reaffirmation as supported (C1-C3). The supported statement is narrower: at the reported configuration, no positive gain of error-driven routing over random routing was supported; a FIFO window beat the recurrent state on skewed and bursty mixes and lost on balanced.
3. To settle the open items, ask Nick for four things from his local run (not in the repo): the experiment script, the per-seed results JSON, the run manifest (which configurations ran, with what beta/tau), and the 8e control results.
4. Stage 3 (trained projections) and the Sylloge proposal are separate decisions, untouched by this report.
