for the reviewer, with krisis-spec-v3.txt and the round 3 review.

For each: what v4 will say, and what to check. Fight anything
under-specified.

=====================================================================
1. TWO-TRACK RELEASE
v4: Foundation Release (contract, auth, abstention, audit,
reliability; NO quality-gain claim) and Selector Promotion (optional
feature profile beats equal-budget baselines on held-out data) are
separate gates with separately labeled reports.
Check: no wording anywhere lets Foundation imply a quality gain.

=====================================================================
2. GROUNDED PROFILE HARD REJECTIONS
v4: in a grounded profile, unsupported and contradicted are hard
rejections BEFORE scoring; unverified and verifier_unavailable are
non-grounded states, never zero-contradiction. Non-grounded profiles
may not claim grounded selection. Fixture A rewritten with an
explicit profile, numeric features, and tau.
Check: c1 (fluent, unsupported) is rejected pre-score; c2 selected
only if it clears the acceptance threshold.

=====================================================================
3. POLICY MANIFEST EXAMPLE (the core of v4)
v4 ships a worked manifest: exact score equation, feature
domains/units, calibration IDs, question-class -> profile mapping,
missing-feature fallback branch, tie order, tau with score >= tau
as pass, NaN/out-of-range rejection. Numeric fixtures decidable
without a model call.
Check: a second implementation could reproduce every score and
outcome from the manifest alone.

=====================================================================
4. VERIFIER OWNERSHIP + FAIL-CLOSED AUDIT (new, mine)
v4: Kybernetes owns verify_answer_claims(answer, cited_spans,
snapshot); shared library implements; Dianoia may call it later;
Krisis consumes typed verdicts. Caveat written in: Kybernetes also
generates candidates, so independence rests on Dokime auditing the
verifier's false-support and false-reject rates before every
manifest freeze. If the audit crosses agreed error bounds, grounded
profiles deactivate automatically (fail closed). Verdicts can only
be abstained from, never overridden.
Check: the fail-closed trigger has an owner, a threshold, and a
test. Challenge the ownership choice if you see a cleaner home.

=====================================================================
5. QUESTION-CLASS ROUTING (new, mine)
v4: class assignment is part of the versioned manifest - explicit
rules or a named classifier + version. Unclassified/ambiguous
queries fall to a DEFAULT profile (most conservative: eligibility +
support only, abstain-leaning). Classification logged per decision
(class, rule/classifier version, confidence). A classifier is itself
Dokime-audited for misclassification rate. Fixtures: no-class match
-> default; two-class match -> documented precedence.
Check: no request can reach scoring without a deterministic class
decision.

=====================================================================
6. SAME-CANDIDATE-SET EVALUATION ARM
v4: selection ablations run over identical frozen candidate sets
(same models, prompts, evidence, acquisition cost): eligibility-
only, likelihood-only where available, support-only, full profile.
Separately: whole n=2 pipeline vs n=1 direct baseline with all
generation failures and tokens counted. Foundation and Promotion
verdicts reported separately.
Check: no claim attributes n=2-vs-n=1 gains to Krisis selection.

=====================================================================
7. COMPLETE OUTCOME ENUM
v4: one enum - SELECTED, NO_AUTHORIZED_CANDIDATE (authorization
only), NO_VALID_CANDIDATE (provenance/contradiction/support), 
QUALITY_BELOW_THRESHOLD, VERIFIER_UNAVAILABLE, BUDGET_EXHAUSTED,
STALE, SCHEMA_INVALID, UPSTREAM_GENERATION_FAILED, CANCELLED -
with deterministic precedence for mixed reasons, a Krisis-decision
vs Kybernetes-failure split, and retry limits.
Check: every fixture maps to exactly one enum value.

=====================================================================
