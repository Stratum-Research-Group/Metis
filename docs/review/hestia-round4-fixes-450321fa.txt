NEW FINDINGS
1. HIGH - The live hardware integration test times out when checking CLI status.
   tests/test_integration.py:71-85,114-119; src/hestia/cli/__init__.py:109-115
   uvicorn.Server.serve() runs as a task on this test's event loop, then CliRunner invokes the synchronous status command on that same loop. Its blocking httpx.get waits for /health, but the server cannot service the request until the synchronous CLI returns. Reproduced using a minimal live FastAPI/Uvicorn server with the same structure: CLI exits with httpx.ReadTimeout, while /health returns 200 once the loop resumes. Run CLI in a worker thread (asyncio.to_thread around CliRunner.invoke), or spawn a real CLI subprocess asynchronously. Set a bounded readiness check and preserve exception context when asserting the result. The hardware-gated test did not exercise this on the review machine.

2. MED - Idle auto-unload can still stop a model freshly used while draining an older request.
   src/hestia/server/__init__.py:201-226,228-241,304-320
   The new idle-age check happens once after the lock is acquired, before the in-flight drain loop. A model that was idle long enough when the check began may have an in-flight request; while waiting for it to finish, request_finished calls _touch. After the drain, _unload_model stops the now-fresh model without rechecking age. Reproduced by setting old last_activity and one in-flight request, finishing it during the drain sleep: _unload_model(..., is_idle_check=True) returned True and backend.stop ran. Recheck idle age after draining, immediately before popping/stopping the backend. Add a deterministic regression that finishes an in-flight request while an idle-triggered unload waits and asserts no stop, no unload report. Keep explicit unload semantics separate.
