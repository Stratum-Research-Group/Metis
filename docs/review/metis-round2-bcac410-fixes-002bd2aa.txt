   extras to get pytest. Keep lockfile-backed installation reproducible.

4. HIGH - Final status discards the verifier's verdict
   Files: kybernetes/kybernetes/engine/pipeline.py:434-445,453-485,507,521;
          tests/test_stack_smoke.py: final status assertion.
   The VERIFY stage records v_report.status, but final_status is recalculated
   solely from whether citations/tool_output exist. A rejecting verifier
   returning INSUFFICIENT_EVIDENCE with score=0 still produced completed.status
   'verified' and show_work.verifier_status 'verified' in a CPU probe.
   Fix: final status must follow the actual verification result and typed stage
   failures/unavailability. Preserve the verdict consistently in SSE, trace,
   session and UI. Citations existing is not proof of correctness. Mock/demo
   evidence must not be promoted to real factual verification merely by presence.
   Regression: inject conflicting, insufficient, unavailable and successful
   verifier results into the same cited turn; assert every output retains the
   actual verdict. Revise the smoke expectation if it currently blesses demo
   evidence as factual verification; retain negative coverage rather than delete it.

5. HIGH - Heuristic Krisis adapter accepts unresolved or unsupported citations
   File: kybernetes/kybernetes/adapters/krisis.py:60-81.
   Repro: with a retrieved Metis citation, response 'The moon is cheese [999].'
   returns VERIFIED, unsupported_claims=0. The condition at 63 only rejects when
   no known marker AND no '[' occurs, so any bracket bypasses it. Even a valid
   marker establishes reference syntax, not that the answer's claim is supported.
   Fix: reject unknown/unresolved markers, validate claims against selected
   evidence through the intended real verification boundary, and expose heuristic
   checks as heuristic/unverified when claim support has not been checked.
   Propagate is_simulated and verifier mode into final events/trace/UI; the
   pipeline currently records only status and score from this report.
   Regression: [999], malformed markers, no citations, known marker attached to
   unrelated claims, contradictions and genuinely supported claims. No retrieval
   score or marker match should stand in for semantic claim verification.
