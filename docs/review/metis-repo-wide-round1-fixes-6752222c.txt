0. SCOPE, RESULT AND HOW TO USE THIS

This replaces the narrow dashboard-dependency review with a repo-wide pass across
all 11 modules, root setup, launcher, CI, cross-module contracts and documentation.
It is not a declaration that the repository is defect-free. It lists defects found,
integration gaps and the checks not performed. It does not imply every algorithm,
benchmark or source line has been independently audited.

Result: NOT CLEAN. Fix startup and authentication first, then approval integrity,
fail-closed selection/training evidence, serving lifecycle and live integration.
The dashboard remains a proposed feature, not a substitute for these repairs.

No tracked source was changed. No GPU jobs, model downloads, training, production
servers or real outbound actions were run. Targeted reproductions used temporary
files, in-process HTTP transports, fake action callbacks and mocked Uvicorn.
A wheel build was inspected. Source compilation and shell syntax checks passed.

Tests ran in a separate light Python 3.12.14 environment with current available
CPU dependencies, NOT the repository's uv.lock environment. PYTHONPATH explicitly
included module source roots. Torch and sentence-transformers were not installed.
Offline model-download flags were set. Treat this as bounded regression evidence,
not proof of locked-install compatibility or real serving.

1. P0 - RESTORE THE PROSOPON SERVER ENTRYPOINT [REPRODUCED]

Where: prosopon/prosopon/cli.py:29-83; scripts/run_stack.sh:119-136.
Observed: Click invocation of `serve --no-mock` exits 0 and calls Uvicorn zero times.
`run` exits 1 with NameError("name 'tls' is not defined"). serve only constructs cfg;
the launch body is inside the run alias, whose function has no tls/cfg/bind_host
locals. The shipped launcher calls serve, so it does not launch the UI.

Fix: put TLS setup, app creation, banner and uvicorn.run in serve or a shared
explicit function. Make run a thin alias. Generate any startup PIN on the SAME
PairingManager instance attached to the running app, not a second manager.
Tests: CliRunner plus patched Uvicorn must prove serve calls it exactly once with
correct host, port, app and TLS paths; run must use the same path. Add a process
startup check that waits for /api/health and fails if the UI process exits early.
Do not start real inference in this test.

2. P0 - CLOSE UNAUTHENTICATED LAN SELF-PAIRING [REPRODUCED]

Where: prosopon/prosopon/server.py:108-121.
The PIN endpoint comment promises loopback/already-authenticated access, but there
is no check or auth dependency. In LAN config, a simulated remote client observed:
GET sessions without token=401; POST auth/pin=200; POST auth/pair using returned
PIN=200; GET sessions with that newly issued token=200.

Fix: PIN creation must be an owner-authorized operation. Reject unpaired remote
callers; prefer an authenticated local owner flow or explicit terminal control.
Do not return an owner pairing secret to whoever requests it. Add rate limits,
expiry, correct one-use semantics and logs that do not contain PINs/tokens.
Tests: unauthenticated remote PIN creation rejected; ordinary remote pairing needs
an independently issued valid PIN; expiry, replay, lockout and concurrent requests.

3. P0 - AUTHENTICATE THE CONTROL BOUNDARY, INCLUDING LOOPBACK [SOURCE]

Where: kybernetes/kybernetes/server/app.py:57-63,87-130;
prosopon/prosopon/server.py:81-98; hestia/src/hestia/api/app.py:317-359.
Kybernetes chat, approvals, cancellation, traces and budget routes have no owner
or service authentication. CORS allows '*' with credentials. Prosopon exempts
loopback clients from token auth. Hestia manage routes are unauthenticated.
Binding locally is exposure reduction, not caller authentication. Browser access
to loopback may be possible depending on browser protections; exploitability was
not tested. Direct Kybernetes access also bypasses Prosopon's pairing gate.

Fix: define a dedicated authenticated guard with no loopback exemption for admin
reads/writes and approval actions. Protect internal Kybernetes/Hestia routes with
service credentials or a private authenticated transport. Use explicit origins,
Host validation, and CSRF protection if cookie sessions are used. Authenticate
approval resolution against the owner and bind it to the relevant request.
Keep health payloads public only if deliberately minimal and non-sensitive.
Tests: unauthenticated local AND remote access rejected, allowed origins/Hosts
accepted, unexpected ones rejected; direct upstream access cannot bypass the UI.
Do not expose LAN admin controls until this is in place.

4. P1 - MAKE PAIRING AND REVOCATION OPERATE ON LIVE SERVER STATE [REPRODUCED]

Where: prosopon/prosopon/cli.py:70-73,86-103;
prosopon/prosopon/auth/pairing.py:26-39,41-46,85-114.
PINs are in-memory. A separately created CLI manager's PIN cannot be verified by
the server manager. Running `pair` is not a working way to issue a server PIN.
Tokens are loaded once; another manager's revoke_all updates disk, but the running
manager continues validating its cached token. This was reproduced with two
managers sharing one temporary directory.

Fix: make CLI commands call a protected server control operation, or implement a
single coordinated state authority with safe reload/version checks. Do not share
PINs through insecure plaintext endpoints. Protect persisted tokens with owner-only
permissions; prefer hashed token storage. Define multi-process behavior explicitly.
Tests: CLI-issued PIN works on the running instance; CLI revocation immediately
invalidates it there; restart retains correct revoked state; concurrent pairing
and writes do not lose state.

5. P0 - BIND FILE APPROVALS TO ACTUAL WRITE CONTENT [REPRODUCED]

Where: phylax/phylax/gateway/file_adapter.py:62-105, especially line 102.
write_text passes only {'content_bytes': len(encoded)} into authorization. The
closure captures content separately. An approval for four bytes allowed an
arbitrary different four-byte payload in a temporary file. Argument-digest
protection cannot detect a content swap when the content is absent from the digest.

Fix: bind the exact content digest, encoding, canonical destination, operation
and relevant overwrite options to approval. Validate the same bytes at execution.
Do not put private full file bodies in audit logs. Include a digest/size and a
reviewable summary instead. Canonical resource handling must agree between decide
and execution. Audit other adapters for hidden closure parameters.
Tests: equal-size changed content, changed encoding, target and overwrite behavior
must fail; exact approved content succeeds once; retry/replay fails.

6. P0 - AUDIT PRE-APPROVED ACTIONS BEFORE THEIR SIDE EFFECT [REPRODUCED]

Where: phylax/phylax/gateway/gateway.py:121-163,185-225.
The pre-approved path consumes approval then invokes action_fn without writing a
fresh pre-execution audit record. Receipt logging happens after execution. With
AuditLogger.log_event patched to raise a disk-failure exception AFTER owner
approval, a fake action callback still executed, then PhylaxAuditFailureError
was raised. This contradicts the blanket fail-closed claim in phylax/README.md:14.

Fix: durably log authorized execution intent before executing, including consumed
approval binding; if that write fails, do not call the action. Separately represent
an executed action whose receipt write fails as executed/audit-unacknowledged,
never as a safe unexecuted denial. Do not retry side effects automatically.
Tests: pre-execution audit failure causes zero callback calls; post-execution audit
failure reports indeterminate recording and never retries; replay still fails.
Document crash-between-intent-and-receipt behavior and recovery.

7. P1 - DO NOT OVERSTATE FILE PATH RACE PROTECTION [SOURCE]

Where: phylax/phylax/gateway/file_adapter.py:28-46,74-94;
phylax/README.md:15.
O_NOFOLLOW checks only the final path component. Parent directories can still
change after policy canonicalization. read compares inode only, not device and
verified authorized ancestry. write creates parents and uses a predictable
PID-only temp name. The code does not justify a blanket claim that TOCTOU races
are prevented. A full race exploit was not run.

Fix: use verified directory descriptors and descriptor-relative operations within
an allowlisted root; prevent ancestor symlink substitution. Use unique exclusive
creation for temp files, lock concurrent writes, verify file type/device identity,
and define durable rename/directory-fsync guarantees.
Tests: parent symlink swaps, final-component swaps, concurrent same-process writes,
pre-existing temp files, cross-device behavior and cleanup. No outside-root access.
