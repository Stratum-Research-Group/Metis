HESTIA - model serving layer. New project scaffold and first build. Follow these instructions exactly. Ask before deviating.

CONTEXT
Hestia is the model serving utility for a local AI stack. Today every project (LTHCM, Dianoia) would load its own copy of a model. Hestia makes models a shared utility: one service hosts them, everything else calls an API.

HARD CONSTRAINTS
- Everything local: no paid APIs, no hosted models.
- Single GPU for now: RTX 5060 Ti 16 GB (Blackwell). Design the backend behind an interface so a second GPU and vLLM can be added later without a rewrite.
- VRAM-aware: 16 GB budget. Co-load models when their aggregate estimated VRAM fits; never load one that does not fit. At load time, compare each model's estimate (GGUF file size plus context/KV-cache overhead) with live free VRAM from nvidia-smi.

BUILD, IN THIS ORDER

1. REPO SCAFFOLD
- New repo "hestia", Python package, pyproject.toml. Add *.txt to .gitignore.
- Model registry as a YAML file: per model - name, type (chat | embedding), GGUF path, quantization, context size, default sampling params, vram_estimate_mb (GGUF size plus context/KV overhead heuristic).
- hestia.yaml service config: listen port, llama.cpp binary path, backend port range for spawned processes (e.g. 8081-8099), default idle timeout (10 min), log level.

2. SERVER MANAGER
- Launches and manages llama.cpp server processes for registered models. Each loaded model gets its own process on the next free port from the configured range.
- Server manager derives llama.cpp launch flags from registry fields: --ctx-size from context size, -ngl for full GPU offload, --embedding for embedding-type models, --port from the allocated port.
- Lazy load on first API request for a registered-but-unloaded model, with a per-model load lock to prevent duplicate starts. If it will not fit, unload the longest-idle model and retry placement; if it still will not fit, return a clear error.
- Health checks, logs capture, automatic unload after the configured idle timeout. On unload, drain in-flight requests before stopping the process.
- On a backend crash, restart with exponential backoff, at most 3 retries; then mark the model failed and surface that state in /health.
- Track aggregate VRAM reservations so multiple models can run concurrently when they fit.

3. API
- Clients specify which model by name in the request body (standard OpenAI "model" field). Hestia routes to the matching registry entry and its backend process.
- OpenAI-compatible /v1/chat/completions with SSE stream:true support from the first build.
- OpenAI-compatible /v1/embeddings for embedding-type models.
- /models lists the registry with loaded/unloaded/failed status.
- /health reports service and per-model health.

4. CLI
- hestia list / hestia load <name> / hestia unload <name> / hestia status showing VRAM use per model and total GPU utilisation.

OUT OF SCOPE
- vLLM backend, second GPU / multi-GPU sharding, auth, remote access, fine-tuning, raw-text /v1/completions.

TESTING
- Unit tests for VRAM budgeting, placement logic, and load locking; integration test the demo scenario end-to-end.

DEMO
- Register one 8B GGUF instruct model and one small embedding model.
- hestia load the chat model, answer one curl chat request (including stream:true), hestia status shows it loaded.
- curl one /v1/embeddings request to trigger lazy-load of the embedding model; hestia status shows both loaded.
- Auto-unload fires after idle timeout; a new request lazy-loads again.
